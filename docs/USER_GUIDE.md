# Scrap Mechanic Save Editor

A polished offline desktop editor for Scrap Mechanic Survival, Creative/Sandbox, and Custom Game saves. It combines a Python save engine with an HTML/CSS interface embedded directly in a Windows application—there is no website, localhost server, browser window, account, or save upload.

> [!IMPORTANT]
> Close Scrap Mechanic before editing. The editor automatically keeps timestamped versions under `%LOCALAPPDATA%\ScrapMechanicSaveEditor\Backups`, outside every game save folder.

## Download

Download the latest Windows ZIP from [Releases](https://github.com/MrBoxik/Scrap-Mechanic-Save-Editor/releases/latest), extract
the complete folder, and open `ScrapMechanicSaveEditor.exe`. Keep the
`_internal` folder beside the executable. The packaged application does not
require Python.

### Requirements and automatic setup

- Windows 10 or 11, 64-bit;
- Scrap Mechanic installed through Steam;
- no Python, browser extension, developer mode, or game-file patch.

The editor locates Steam through the Windows registry, reads every configured
`libraryfolders.vdf`, and validates Scrap Mechanic's app manifest. Steam, the
game, and the optional official Mod Tool may all be on different drives. Every
local `User_*` profile is detected instead of assuming one Steam ID.

Open **Settings → Installation check** to see exactly what was detected. Rare
portable setups can use `STEAM_ROOT`, `STEAM_EXE`,
`SCRAP_MECHANIC_GAME_ROOT`, or `SCRAP_MECHANIC_MOD_TOOL_ROOT` environment
overrides; invalid overrides are ignored rather than trusted.

Releases include a SHA-256 checksum. Verify it in PowerShell with:

```powershell
Get-FileHash .\ScrapMechanicSaveEditor.exe -Algorithm SHA256
```

- Keeps automatic, manual, and edited-copy versions outside the game save folders, with a built-in history and safe restore.
- Edits player health, maximum health, oxygen, maximum oxygen, all four food perks, and the exact saved world position.
- Teleports a player to placed/permanent beds or death bags, forgets a placed bed, and clears oil, chemical, and blocked-respawn flags.
- Clears stored death markers and controls whether bots can target player-built creations.
- Edits linked player beacons with the game's 24 real symbols and eight exact color swatches, updating both manager state and physical beacon storage.
- Edits every quarter-day tile in the Survival forecast queue, adds future days, and skips the current day.
- Inspects registered worlds and resets saved tornadoes plus their visited-desert-cell cooldown when requested.
- Cancels active raids stored by the Survival raid manager.
- Edits progression values including seed tier, encrypted vault total, warehouse console unlock, and beacon crafting state.
- Lists all 46 quests from the installed game data and marks individual quests—or every quest—complete.
- Removes completed active quest objects and tracked references while preserving unrelated quest-manager data.
- Unlocks all 528 installed Craftbot recipe outputs individually or together, with game names and icons.
- Unlocks all 27 logbook entries.
- Reads and safely updates the Steam user's global clothing profile with 253 named customizations and its required checksum, including individual lock/unlock and undo-staged controls.
- Edits gender, all nine appearance/equipment slots, and palette indices in the global character profile, with the actual high-resolution garment icons generated by the game.
- Manages local creation Blueprints: metadata editing, duplication, ZIP archiving, and safe ZIP import.
- Edits world day/time and can pause or resume the day cycle.
- Edits the 40-slot player backpack/hotbar and every other validated container.
- Loads 1,352 game catalogue entries with names, categories, stack limits, descriptions, and high-resolution game icons.
- Supports search, filters, drag and drop, right-click replacement, quantities, and background catalogue loading.
- Opens every uncached world with its exact terrain atlas immediately; an optional Build HD map action captures the complete real 3D world and reuses the validated high-resolution PNG on later visits.
- Keeps destinations, filters, player position, and player beacons as a live interactive overlay above the generated image, so tracking stays current without rebuilding the background.
- Includes a Map Companion launcher with a live in-game minimap, M-key world map, persistent directional or circular exploration fog, installed-game POI artwork, coloured player beacons, and independent full-map/minimap category filters.
- Keeps far discovered destinations at the minimap edge and scales them by distance, while exact world-space coordinates keep the minimap and full-map player markers aligned.
- Shows the original crisp installed-game thumbnail for every terrain POI on hover and keeps it open when selected, avoiding the perspective smear inherent in flattening isometric locations.
- Provides map search, destination filters, hover details, wheel zoom, fit-to-view, drag panning, the complete Native preview map, and a flyable complete-world 3D view built from installed terrain, models, transparent decals, compiled transforms, players, units, and saved creations.
- Resolves named game-material textures, UvMaterial detail masks, Collada scale, explicit water surfaces, and deferred mesh decals so bridges, packing stations, ruins, dungeons, and crystal props render cleanly in Real 3D.
- Edits difficulty and existing multiplayer/physics settings; advanced mode also exposes seed, flags, and game tick.
- Validates SQLite integrity before loading and after saving.
- Saves edited copies to the external archive or writes to the game with an automatic timestamped backup.
- Creates a separate timestamped backup before writing the global clothing `unlock` profile.
- Reports the map/3D performance cache in Settings, cleans abandoned temporary files automatically, keeps the cache below 4 GB, and can clear it without touching saves or backups.

## Safe workflow

1. Exit Scrap Mechanic completely.
2. Open the editor and select a detected world save.
3. Make the changes you want.
4. Optionally use **Save edited copy** to keep a checkpoint in the external archive.
5. Use **Save to game** to write the staged changes to the world.
6. Start Scrap Mechanic and test the edited save.

## Map Companion

Use **Launch with Map Companion** on the home page or its dedicated settings
page. The packaged editor starts Scrap Mechanic normally through Steam and
relaunches its own executable in read-only companion mode—there are no loose
scripts to copy and no machine-specific launcher path.

The companion reads live position and facing from the running Windows process,
but builds maps only from private SQLite snapshots. It never writes to the
active game database. Its settings, exploration history, generated lossless
map, and private runtime snapshots are stored below
`%LOCALAPPDATA%\ScrapMechanicMapCompanion`; launch diagnostics remain with the
editor under `%LOCALAPPDATA%\ScrapMechanicSaveEditor`.

The companion is Survival-only. It uses the terrain overview immediately and
reuses an HD map when one has already been built in the editor. To upgrade a
world, close the game, load its save in the editor, and choose **Build HD map**.
The next companion session picks up that image automatically. Companion
settings include an interactive preview of the actual renderer; M opens its
full-map preview without starting the game or changing exploration history.

The official Mod Tool can build an integrated minimap only as a **Custom
Game**; Steam Workshop mods cannot inject executable UI into arbitrary existing
vanilla Survival worlds. The external companion is therefore the supported
option for existing saves. See the [verified Workshop and Mod Tool feasibility
report](WORKSHOP_MOD_FEASIBILITY.md) before working on a Workshop edition.

## Run from source

Python 3.11 or newer is required. Run these commands from the repository root:

```powershell
cd app
python -m pip install -r requirements-desktop.txt
python .\run_desktop_editor.py
```

The legacy Tkinter interface remains available for diagnostics:

```powershell
python .\scrap_mechanic_save_editor.py
```

Read-only command-line inspection:

```powershell
python .\scrap_mechanic_save_editor.py --inspect "C:\path\to\save.db"
```

## Build the Windows app

Install PyInstaller, then build the fast-starting portable release:

```powershell
python -m pip install pyinstaller
python .\build_release.py
```

Run build commands from `app/`. The result is a versioned folder and Windows
ZIP under `releases/` at the repository root.
`build_desktop.py --onefile` remains available for diagnostics, but it is not
the public format because it must unpack the runtime on every launch.

Before publishing, run the same checks used by CI:

```powershell
python .\tools\release_check.py
python -m unittest discover -v
```

## Technical notes

World saves are SQLite databases containing ordinary tables and, depending on the mode, compressed binary Lua state. The editor detects capabilities from each database, preserves unknown fields and keys, and updates exact source rows instead of rebuilding the database. Survival-only controls are disabled for Creative/Sandbox and Custom Game worlds that do not contain those managers.

All world archives are stored below `%LOCALAPPDATA%\ScrapMechanicSaveEditor\Backups`. Restoring a version first archives the current target again, giving the restore operation its own recovery point. These archives are never placed below `User\...\Save`, so Scrap Mechanic will not list them as worlds.

Offline quest completion updates the quest manager's completed list, removes active quest objects and tracked references, and unlocks known schematic rewards. It cannot replay live scripted world events, Steam achievements, physical item rewards, or automatic next-quest activation. Those limitations are shown beside the quest controls.

Clothing and character appearance are not stored in a world database. They live in the Steam user's global binary `unlock` and `character` profiles. The editor verifies the unlock file's Steam-ID-bound CRC-32 checksum, validates the exact character v2 layout, and archives either file before applying a change.

Survival weather, tornado, and registered-world services live in engine Lua storage channels. Weather operations mirror the installed `WeatherManager.lua` queue rules, while tornado reset returns the manager to the same empty structure it creates on first use. Elevator, trader, dungeon, and named-fire service internals remain read-only because changing one side of those linked systems can orphan world objects.

Inventory slots use UUIDs plus metadata and quantity. Existing tool instances may safely have their quantity changed, but the editor will not fabricate a tool instance from a catalogue UUID because tools also require a corresponding `Tool` table record.

The world map keeps the save's exact generated terrain grid, rotations, saved elevation, and cliff levels. **2D map** is an immediate, searchable overview without noisy enemy or loose-creation pins. **3D world** progressively loads every generated placement as one persistent, full-detail scene and keeps it resident while you switch back to 2D. Players, units, and saved player creations are rendered as installed 3D meshes at their saved positions. **Fit** gives an overhead view in either mode. Camera movement changes only the view; it does not recull or re-upload the world. **Build HD map** captures a reusable geometry-based overhead image and can be cancelled without discarding the terrain overview.

The editor decodes FBX/DAE/OBJ and supported proprietary `.mesh` files through Scrap Mechanic's installed Assimp library, GPU-instances repeated objects, expands nested prefabs and build-quest blueprints, and loads blueprint shapes, harvestables, terrain splat layers, safe ground decals, and shaped water/chemical surfaces. It follows installed material profiles for UV-channel selection, paint masks, transparency, specular response, and glow. Dragging orbits a stable focus point, right-drag pans, **WASD** moves that focus through the world, **Q/E** rotates, **Space/Ctrl** moves vertically, and **Shift** boosts. Resolved scenes, meshes, converted textures, and save-entity assemblies are cached outside the game folders, so repeat openings are substantially faster. Runtime-only projector volumes, animated effects, and kinematics are deferred when a static approximation would be misleading. See [the full 3D renderer design and verified coverage](FULL_3D_MAP_RENDERER.md).
